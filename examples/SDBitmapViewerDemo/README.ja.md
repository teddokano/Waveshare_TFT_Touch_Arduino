# SDBitmapViewerDemo

[English](README.md) | 日本語

[Waveshare 2.8inch TFT Touch Shield](https://www.waveshare.com/2.8inch-tft-touch-shield.htm)(SKU: 10684)用の、タッチ操作による画像ビューアです。シールドのmicroSDスロットにある24ビットBMPを、タップ・スワイプ・長押し、またはボード上のSW2/SW3ボタンで切り替えながら表示し、放置するとスクリーンセーバーに移行します。

これは [`SDBitmapViewer`](../SDBitmapViewer) の発展版です。あちらは移植性を重視したサンプルでこのライブラリが対応する全ボードで動きますが、こちらは **FRDM-MCXA153とFRDM-MCXN947専用**で、RAMを惜しまず使って画面切り替えを速くしています。それ以外のボードでビルドすると、明示的な `#error` で停止します。

## 必要なもの

- 本シールドを装着したFRDM-MCXA153またはFRDM-MCXN947
- [mcx-arduino-core](https://github.com/teddokano/mcx-arduino-core) **0.4.1以降** — これより古いバージョンは要求したSPIクロックが実際には反映されず、全体が非常に遅くなります
- microSDカード(FAT16またはFAT32、32GB以下)
- Arduino IDE同梱の `SD` ライブラリ

BMPファイルは **24ビット無圧縮**(BI_RGB)である必要があります — 画像編集ソフトで「24ビットビットマップ」として保存した既定の形式です。320x240より大きい画像は画面サイズに切り詰められ、小さい画像は左上を基準に描画されます。

## 使いはじめ

1. 24ビットBMPファイルをカードにコピーします。
2. [`PLAYLIST.JSN`](PLAYLIST.JSN) をカードのルートにコピーし、パスを自分のファイルに合わせて書き換えます。
3. ボードを選んで書き込み、シリアルモニタを115200 baudで開きます。

`/PLAYLIST.JSN` が無い場合は、カードのルートにある `.bmp` を、FATのディレクトリに並んでいる順でそのまま表示します。

## 操作

| 操作 | 横画面(既定) | 縦画面(`"portrait": true`) |
| --- | --- | --- |
| 画面上半分をタッチ | — | 次の画像、上から下へワイプ |
| 画面下半分をタッチ | — | 前の画像、下から上へワイプ |
| タップ | 次の画像 | (上記のとおり位置で決まる) |
| スワイプ | 左=次、右=前 | 使用しない |
| 長押し(約0.6秒静止) | ギャラリーを開く | ギャラリーを開く |
| ギャラリー表示中のタッチ | そのサムネイルの画像へ | そのサムネイルの画像へ |
| スクリーンセーバー中のタッチ | 元の画像に戻る | 元の画像に戻る |

横画面でスワイプと判定されるのは、移動量が20px以上あり、かつ垂直方向より水平方向の移動が大きい場合です。これに満たない動きはタップとして扱われます。

長押しは指を離すのを待たず、押している最中に発火します。判定されるのは、タッチ開始位置から10px以内に留まっている場合のみです。

**縦画面モード**は、ボードを横倒しにして持つためのものです。変わるのはタッチの解釈だけで、指がどちらへ動いたかではなく*どこに触れたか*で判断します。ボードを回して持つと、パネルの長辺方向へフリックするのが窮屈なためです。画面上半分に触れると次の画像が上から下へ、下半分に触れると前の画像が下から上へワイプします。このモードではスワイプは一切読まず、ワイプ方向は交互の既定値ではなく操作した位置で決まります。なお、ボードをどちら向きに持っているかはスケッチからは知りようがないため、パネル自体は横画面のまま駆動されます。画像が自動で回転することはありません。

スクリーンセーバーを解除するタッチは、解除するだけです。そのタップやスワイプ自体は破棄されて画像送りには使われないので、1枚行き過ぎてしまうことはありません。

### ギャラリー

長押しすると、リストの先頭9枚をサムネイルにした3x3のギャラリーに切り替わります。マスをタッチするとその画像が全画面で開きます。画像のないマスをタッチしても何も起こりません。SW2/SW3の操作やスクリーンセーバーの開始など、画像を描画する動作があればギャラリーからも抜けます。

1マスは106x80で、間に2pxの隙間があります。サムネイルは縦横比を保ったままマスに収まるよう縮小し、余った分は中央に配置します。開けない/デコードできないファイルのマスは、全画面描画の失敗時と同じ赤で塗ります。

描画先の行に対応する行だけを読み、それ以外の行は読まずにシークで飛ばします。3x3なら1/3縮小になるので、9枚分でも全画面描画9回分ではなく**約3回分**の読み出しで済みます。所要時間はシリアルに出ます。

```
long press -> gallery
  gallery of 9 in 3848 ms
```

これはFRDM-MCXA153での実測値です。全画面描画1枚が993〜1394msだったので、サムネイル9枚で1枚の約3.2倍。行スキップの効果はここに出ています。

### これ以上速くならない理由

描画側ではありません。2つの実測が示しています。1行のコストは、960バイトを1回で読んでLCD転送1回でも、192バイト×5回に分けてLCD転送5回でも、同じ約5msです。さらに、行ごとのシークをやめて不要な行も読み飛ばさず読む順次読みに変えたら、**遅くなりました**(3797ms → 6946ms)。この2式を解くと、960バイトの読み出しに約3.2ms、シークに約2.2ms。**約300KB/s**です。

原因はバスではなく、同梱のSDライブラリです。カードを**4MHz**で動かしています。`SD.begin()` は `SPI_HALF_SPEED` を決め打ちしており、このバージョンでは `begin(clock, csPin)` も同じで、クロック引数は無視されます。読み出しも `SPI.transfer()` を1バイトずつ呼ぶ作りです。4MHzで960バイトは1.92msなので、実測3.2msとの差がバイトごとの呼び出しコストにあたります。スケッチ側からは変えられません。`SDClass` は `Sd2Card` をprivateに持っているため、これを変える `setSpiClock()` に手が届きません。

つまりこのスケッチでは、LCDが24MHz、カードが4MHzで動いています。ギャラリーはこのSDライブラリでの上限に達しています。

縦画面モードでも、パネル自体は横画面のまま駆動しているのでギャラリーの並びも横画面のままです。ボードを倒して持つと、行方向ではなく列方向に並んで見えます。マスの選択はどちらの場合もタッチした位置で決まります。

### ボード上のボタン

FRDMボードの **SW2** / **SW3** で、画面に触れずに同じリストを送れます。縦画面モードでも同じです。SW2で1枚戻り、SW3で1枚進みます。押した回数が数えられるので、ダブルクリックで2枚、トリプルクリックで3枚というように動きます。

| 操作 | 動作 |
| --- | --- |
| SW3を1回 | 次の画像。上から下へワイプ |
| SW3を素早く2回 | 2枚先へ |
| SW2を素早く3回 | 3枚戻る。下から上へワイプ |
| スクリーンセーバー中にどちらか | 元の画像に戻る |

途中の画像は描画されません。最後のクリックから400ms待ってから、まとめて1回だけ移動します。1回の描画に100ms以上かかるため、そうしないと2回目のクリックを受け取る前に描画が始まってしまい、そもそも回数を数えられません。

タップと違い、ワイプ方向はインデックスによる交互ではなく固定です。SW3は常に上から下へ、SW2は常に下から上へワイプするので、リストのどちら向きに動いたかが切り替え方でわかります。

カウントは符号付きの移動量として保持しているので、同じ400msの窓の中で両方のボタンを押すと互いに打ち消し合います。同じ回数ずつ押せば移動しません。SW1はリセットボタンなので使いません。

ボタンの読み取りは `pinMode(SW2, INPUT_PULLUP)` と `digitalRead()` で、mcx-arduino-coreが両ボード向けに定義している `SW2` / `SW3` というピン名をそのまま使っています。なお、この2つのうち一方はチップのISPモード入力を兼ねたピンにあります(FRDM-MCXA153ではSW2、FRDM-MCXN947ではSW3)。そのため、そのボタンを押したままリセットすると、スケッチではなくブートローダが起動することがあります。ボードが立ち上がってから押してください。

## `/PLAYLIST.JSN`

カードのルートに置く1つのファイルで、すべてを設定します。

```json
{
  "playlist":    ["/LOGO.BMP", "/PICS/SUNSET.BMP", "/PICS/MOUNTAIN.BMP"],
  "saver":       ["/PICS/SUNSET.BMP", "/PICS/MOUNTAIN.BMP"],
  "idle_ms":     60000,
  "interval_ms": 5000,
  "portrait":    false,
  "reverse":     false
}
```

| メンバ | 意味 | 省略した場合 |
| --- | --- | --- |
| `playlist` | 表示する画像(この順序で) | カードのルートにある全 `.bmp` を、FATのディレクトリ順で |
| `saver` | スクリーンセーバーが巡回する画像 | スクリーンセーバーは動作しない |
| `idle_ms` | セーバー開始までの無操作時間 | 60000(60秒) |
| `interval_ms` | セーバーの1枚あたりの表示時間 | 5000(5秒) |
| `portrait` | `true` で、ボードを横倒しに持つための位置によるタッチ操作に切り替え | `false` |
| `reverse` | `true` で、すべてのリストを逆順に表示 | `false` |

パスはサブフォルダを指しても構わず、書かれたとおりの順で表示されます。最大32エントリ、1つあたり39文字までです。

拡張子が `.JSON` ではなく `.JSN` なのは、同梱のSDライブラリが8.3形式のファイル名しか扱えず、4文字の拡張子ではそもそも開けないためです。中身は普通のJSONです。

配列だけを書いたファイルも従来どおり受け付け、プレイリストとして読みます。以前の「1ファイル1リスト」形式で用意したカードは、手を加えずにそのまま使えます。

### 編集のヒント

- キーが1つも無い場合や、値の書式が不正な場合は、その項目だけ既定値のまま動きます。つまり新しいキーを書き足していないカードは、これまでどおりの挙動になります。実際に効いている設定は起動時のシリアル出力で確認できます。
- スクリーンセーバーを試すときは、`idle_ms` を `5000` 程度にしておくと毎回1分待たずに済みます。
- `reverse` はプレイリストだけでなく、スクリーンセーバーやディレクトリ走査によるフォールバックにも効きます。画像リストの出どころに関わらず、同じ意味になります。
- パーサはメンバ名を探して直後の値を読む方式で、完全なJSONパーサではありません。そのため、メンバ名とまったく同じ文字列の*パス*があると誤動作します。現実のパスがそうなることはありません。
- macOSのFinderでコピーすると、実ファイルの隣に `._名前.bmp` というメタデータファイルができます。スケッチ側で自動的に除外していますが、カードの中を見て気になった場合はこれです。

## シリアル出力

115200 baudで、読み込んだリスト・有効な設定・画像1枚ごとの描画時間が出力されます。

```
3 BMP file(s) from "playlist" in /PLAYLIST.JSN:
  /LOGO.BMP
  /PICS/SUNSET.BMP
  /PICS/MOUNTAIN.BMP
landscape mode: swipe left / right
screen saver after 60000 ms, advancing every 5000 ms
list order: as written
SW2 = previous, SW3 = next; click n times to move n images
drawing /LOGO.BMP
  top-down, 118 ms
tap
drawing /PICS/SUNSET.BMP
  bottom-up, 121 ms
2 click(s) -> forward 2, wiping down
drawing /PICS/HARBOUR.BMP
  top-down, 119 ms
```

表示される方向はその画像がどう描かれたか(後述)を、ミリ秒は描画そのものにかかった時間を示します。ワイプ方向やボードによる差を比較するのに便利です。

## `/VIEWER.LOG`

画像が切り替わるたびに、同じカードの `/VIEWER.LOG` へ追記されます。各実行の先頭には再起動マーカーが入ります。

```
0 ms  ---- restart ----
1243 ms  drew /LOGO.BMP
8120 ms  drew /PICS/SUNSET.BMP
13355 ms  FAILED /PICS/BROKEN.BMP
```

タイムスタンプはその実行の開始からのミリ秒です。起動のたびにゼロへ戻るため、複数回の実行にまたがるファイルを読めるものにしているのがこの再起動マーカーです。

カードに書き込めない場合は、黙って失敗するのではなくシリアルへ `could not append to /VIEWER.LOG` と出力し、画像表示はそのまま続けます。

## 画面の切り替え

前の画像を先に消すことはせず、新しい画像が1行ずつ上書きしていきます。これにより画像間で黒くフラッシュすることがなくなり、ワイプの方向そのものが目に見える切り替え効果になります。したがって画面より小さい画像の場合、その周囲には前の表示が残ります。

方向は画像インデックスに応じて交互に変わるので、連続する画像は反対方向にワイプします。これはスケッチ冒頭の2つの設定で制御します。

| 設定 | 既定値 | 効果 |
| --- | --- | --- |
| `DRAW_BOTTOM_UP` | `false` | 偶数番目の画像の方向。奇数番目はその逆になる |
| `SWIPE_WIPES_SIDEWAYS` | `false` | `true` にすると、交互の既定値ではなく指を動かした方向にワイプする(横画面なら左右、縦画面なら上下) |

SW2とSW3はこの2つの設定より優先され、交互の状態に関わらず常にそれぞれ下から上・上から下へワイプします。縦画面モードのタッチも同様です。

横方向のワイプにかかるコストは2つのボードで大きく異なります。シリアル出力の時間表示はそれを見るためのものです。

- **FRDM-MCXN947** は画像全体をいったんRAM(150KB)へ展開するため、ファイルは一度シーケンシャルに読むだけで済み、その後はどの方向でもコストは同じです。
- **FRDM-MCXA153** はRAMが24KBしかなくそれができないため、描画しながらカードから読みます。横方向へ進むということはファイルを目に逆らって辿るということで、縦帯ごとに毎行シークが発生し、目に見えて遅くなります。

## トラブルシューティング

**画面が真っ赤になる。** そのファイルを開けなかったか、デコードできませんでした。シリアル出力を確認してください。`unsupported BMP` なら24ビット無圧縮ではありません。それ以外の失敗は、`/PLAYLIST.JSN` に書いたパスがカード上の実体と一致していないということです。SDライブラリはFATの8.3短縮名しか見ないことに注意してください。

**`SD.begin() failed`。** カードが認識されていません。FAT16またはFAT32である必要があります。32GBを超えるカードはSDXCでexFATでフォーマットされており、このSDライブラリでは一切読めません。以前exFATだったカードを変換する場合は、クイックフォーマットではなく完全フォーマットを使ってください。クイックフォーマットでは古いパーティション情報が残ることがあります。

**画像が真っ白になり、描画が這うように遅くなり、その後カードが電源を入れ直すまで応答しなくなる。** 格安の低容量カードで発生しました。同じ種類のカード3枚がすべて同じ挙動で、同じボード・同じシールドで良質なカードは問題ありませんでした。描画を挟まずにファイル全体を読むだけなら毎回成功し、パネルへの書き込みとカードの読み出しが交互になったときにだけ破綻します。このスケッチにこれを補償する仕組みはありません。別のカードを試してください。

**SW2・SW3が効かない。あるいはどちらかを押したままリセットするとボードが応答しない。** 2つのうち一方は、チップのISPモード入力を兼ねたピンにあります(FRDM-MCXA153ではSW2、FRDM-MCXN947ではSW3)。そのボタンを押したままリセットすると、スケッチではなくブートローダが起動します。ボタンを離してリセットし直してください。それ以外の場面で効かない場合は、シリアル出力に `SW2 = previous, SW3 = next` の行が出ているか確認してください。出ていなければ `SD.begin()` から先へ進めていません。

**スクリーンセーバーが始まらない。** 少なくとも1つの読めるパスを含む `saver` メンバが必要です。起動時のシリアル出力を確認してください。設定行に実際に効いているタイムアウトが出ています。

**両方のボードで全体が遅い。** コアのバージョンを確認してください。0.4.1より前のmcx-arduino-coreは、要求したSPIクロックを黙って捨て、初期化時の設定のままバスを使っていました。

## 調整用の定数

スケッチ冒頭にある、上記2つの切り替え設定以外の定数です。

| 定数 | 既定値 | 意味 |
| --- | --- | --- |
| `MAX_BMP_FILES` | 32 | 1つのリストが保持できるエントリ数 |
| `BMP_PATH_LEN` | 40 | パスの最大長(終端文字を含む) |
| `SWIPE_THRESHOLD` | 20 | スワイプと判定するまでの、スワイプ軸方向の移動ピクセル数 |
| `LONG_PRESS_MS` | 600 | 静止したタッチが長押しになるまでの時間 |
| `LONG_PRESS_TOLERANCE` | 10 | 長押しと認めるずれのピクセル数 |
| `GALLERY_COLS` / `GALLERY_ROWS` | 3 / 3 | 長押しで開くギャラリーの分割数。マスの大きさはここから決まる |
| `GALLERY_GUTTER` | 2 | サムネイル間に空ける背景のピクセル数 |
| `MULTI_CLICK_MS` | 400 | SW2/SW3のクリック後、次のクリックを同じカウントに含める時間 |
| `BUTTON_DEBOUNCE_MS` | 25 | SW2/SW3のエッジを有効と認めるまでの安定時間 |
| `CHUNK_PIXELS` | 64 | カードから直接描画する際の、SD読み出し/LCD転送1回あたりのピクセル数 |
| `BAND_PIXELS` | 64 | フレームバッファ経路で、列方向にまとめて処理する帯の幅 |

`IDLE_TIMEOUT_MS` と `SAVER_INTERVAL_MS` は、`/PLAYLIST.JSN` に `idle_ms` / `interval_ms` が無い場合に使われる既定値です。

FRDM-MCXA153で `MAX_BMP_FILES` や `BMP_PATH_LEN` を増やす場合はRAMに注意してください。この2つはスケッチ中で最大の配列のサイズを決めており、リンカスクリプトがスタックに割り当てているのは、メモリレポートが全体の空きとして何と表示しようと2KBだけです。

## ピン割り当て

シールドのPCBで固定されており、配線は不要です。

| 信号 | ピン |
| --- | --- |
| LCD_CS / LCD_DC / LCD_BL | D10 / D7 / D9 |
| TP_CS / TP_IRQ | D4 / D3 |
| SD_CS | D5 |
| SCLK / MOSI / MISO | D13 / D11 / D12 |
